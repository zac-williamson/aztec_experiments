# P04 serial Linux retry — incomplete installation

**This retry is not a Linux build pass.** On 2026-09-12, fresh root dependency installation exceeded its 300-second stage budget. The supervisor recorded the timeout after 388.49 seconds and exited before portal installation, compiler bootstrap, contract/SDK/CRS/application builds or tests. The recovered npm log contains deprecation notices, with no reported fatal package error or successful install summary. The time needed to enforce the deadline is itself an environment observation; its cause is unresolved.

The owned container `billboard-p04-retry-f9caddd4b7` exited with status 1 and `OOMKilled=false`. This flag does not exclude host pressure or other resource problems. Evidence extraction succeeded and removal of that exact container succeeded, both with exit code 0. No global cleanup, additional restart or further retry was performed by this lane.

## Exact experiment

The parent restarted Docker Desktop with user authorization, reported the engine healthy and the original stalled container absent, then completed its browser attempt before authorizing this serial retry. The parent reported substantial remaining host pressure: 24 GiB physical RAM, 10.7 GiB swap used, load around 36 and 18 GiB disk free. These measurements are context, not a demonstrated cause of this timeout.

This retry deliberately changed the earlier environment: it used a container-owned overlay filesystem with **zero mounts**, a 3 GiB memory limit, two CPU quota and `GOMAXPROCS=2`. The original run used a source bind mount, 6 GiB and four CPUs. Therefore this is not a controlled single-variable diagnosis of the earlier stall. In particular, failure here does not establish that host-bind I/O caused the earlier SDK stall.

The image was `docker.io/library/node@sha256:f22d6a1f082c02f292e86929b5b0442ac2e5eaf438a5dea9b1566601c3e05940`; actual runtime was Linux/aarch64 and Node 24.15.0. Docker reported ARM64 manifest digest `sha256:92c191629a40c9ca674e7d5c0c1edf25febb5e2f30f551f187ac71f61595b9f8`. The container had 512 PIDs maximum, all capabilities dropped, no-new-privileges and no exposed ports. No host home, wallet, dependency cache or Docker socket was mounted. The legacy credential-bearing RPC configuration was excluded from the source copy.
