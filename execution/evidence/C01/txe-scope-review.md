2026-09-14. Read-only review of root's service wrapper; no service/test execution by this reviewer.

Pinned `node_modules/@aztec/txe/src/state_machine/index.ts:25` defines chain/version 1/1 and supplies both to AztecNodeService at construction. Its GlobalVariableBuilder is constructed directly inside `TXEStateMachine.create`, with no scope argument or environment setting. `state_machine/global_variable_builder.ts:28` instead calls `makeGlobalVariables()` without overrides. `node_modules/@aztec/stdlib/src/tests/factories.ts:699` defaults seed=1 and sets chainId=seed, version=seed+1. The resulting public/private scope mismatch is a concrete test-environment inconsistency exposed by the new application validation.

Root's `scripts/txe-c01-service.mjs` forwards actual builder arguments to the original implementation, asserts returned chain/version are exactly 1/2, then returns the same fields with version=1. It asserts the constructed node still reports 1/1. No supported TestEnvironment/TXE creation scope override was found in the inspected API; the wrapper is narrower than patching dependencies or removing production configuration checks. Source mismatches fail rather than silently changing arbitrary versions. Its JSON import attribute hook is restricted to the pinned account-artifact directory and addresses Node's loader requirement.

This correction is acceptable for **explicitly labeled consistent-scope TXE tests**. It does not establish genuine-proof, canonical chain or release assurance. Message construction/consumption, roots, application range/scope constraints and nullification code remain the actual implementations. The existing uncorrected failures must remain in evidence. The added wrong-version and wrong-chain initializer tests pair with the normal matching claim control, so the correction must not make incompatible application configuration acceptable.
