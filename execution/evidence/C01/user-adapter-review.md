# C01 user adapter handoff

2026-09-14. The user engine and browser app now consume the fresh portal receipt ABI and logical 11-field note interface. The shared decoder/discovery helper remains root-owned. Storage packing is deliberately not decoded here: the utility returns the logical schema. Explicit depositChainId selects post/hints/withdraw; ambiguous discovery propagates as an error rather than silently choosing another right. Zero private sequence is the new no-post sentinel. The portal address is required; obsolete constructor/address reconstruction was removed. Portal chain/version/rollup are checked against the node and L1 RPC.

Claim receipts carry the actual event's u64 depositNonce, distinct from an L1 transaction nonce. The engine derives the claimed private identity from the exact scoped content and owner, uses the new claim argument order, and builds the V1 exit content with the active L1 receipt nonce. An L2 withdrawal does not clear L1 collateral; unsupported guessed-amount recovery was removed. Saved secret mismatch and missing receipt/secret storage fail explicitly.

New claim secrets use the installed SDK's nonzero random Fr. `config.claimSecretStore.save(scope,record)` and exact hash-verified load/read-back finish before L1 deposit submission. The browser implementation uses encrypted IndexedDB records and awaits transaction completion with strict durability, then decrypts/read-checks the record. There is no deterministic signature recovery, direct secret log, or secret in returned depositInfo. Full wallet backup/export, browser storage eviction recovery and hostile unlocked-page protection remain W02/release concerns.

Encryption contract: AES-256-GCM, random 12-byte IV, 128-bit appended tag; key is SHA256(UTF8(`AZTEC_BB_CLAIM_STORE_KEY_V1\0`) || wallet secret bytes). AAD is JSON array `['AZTEC_BB_CLAIM_STORE_V1',l1ChainId,rollupAddress,rollupVersion,boardAddress,portalAddress,depositor,secretHash]` with canonical scope strings. Plaintext is `{schemaVersion:1,secretHash,secret}`. Envelope is `{schemaVersion:1,iv,ciphertext}`, lowercase hex without 0x. Root's CLI adapter uses the same valid-record encoding. Existing different records cannot be overwritten.

## Actual verification

`node --test scripts/test-c01-user.mjs` under pinned Node24.21 passed **8/8**, zero failures/skips, 0.31 seconds including startup. `user-adapter-final.{json,log}` bind source hashes, exact command and output. Both engine/app and the maintained test script passed syntax checks; whitespace validation passed.

Tests evaluate the complete actual modules, not sliced functions. Actual WebCrypto encryption interoperates with independent Node decryption; fake IndexedDB tests persistence, ciphertext/wallet/scope tampering and a real transaction abort before completion. Public `runBillboardUser` deposit/recovery calls exercise save→readback→send ordering, missing/failing storage, mismatched secret, disabled portal, existing receipt, correct event nonce and stale-receipt rejection. Their node/identity/portal objects are mocks, and the secret-hash function is a deterministic stub for sequencing; these do not claim chain, proof or SDK secret-hash qualification. Production claim/exit codec vectors use the real installed SDK SHA function and ethers encoding.

The initial run's failing `AztecAddress.fromString` call was a real adapter API mistake exposed by installed-package tests; changed to the supported `fromFieldUnsafe(Fr.fromHexString(...))`. `user-adapter-attempt1.log` preserves it; subsequent and final runs pass. No actual browser, RPC, transaction, PXE or proof was run in this lane. Browser durability is API-level qualification in a fake IndexedDB implementation, not a power-loss or storage-eviction test.

Post/claim/withdraw full PXE integration, generated apps, genuine proofs and production sponsorship remain root/downstream gates. Existing ordinary sends still require W01's privacy-preserving fee integration after C03; this change does not establish anonymous fee payment or production readiness. Browser selection UI for multiple private rights remains W02; default ambiguity rejects safely.
