Configuration validates actual private/public context chain and version, nonzero rollup/deployer/censor, and specified economic bounds. Since maximum is at most 2^96−1 and minimum is positive and no greater than maximum, the u128 cooldown multiplication with a u32 base cannot overflow; ceiling division avoids numerator-plus-amount overflow. Initial eligibility addition rejects the declared timestamp horizon. Protocol initializer and PublicImmutable protect one-time config; private portal binding authenticates the original deployer and enqueues a public only-self setter that rejects zero/rebinding and emits scoped Ready.

Claims do not accept a caller-provided portal or execution scope. They read both PublicImmutable values, validate current chain/version and nonzero actors, receipt nonce, secret and amount, reconstruct the scoped content, then call actual `consume_l1_to_l2_message`. Pinned PublicImmutable private read (`aztec/src/state_vars/public_immutable.nr:314–340`) performs an explicit initialization-nullifier existence request and historical hash-bound public-storage read; the unsafe availability oracle is not the sole constraint. Pinned `messaging.nr` reconstructs the full L1/L2 envelope, constrains the actual message root against the anchor, derives the protocol message nullifier, and PrivateContext pushes that nullifier. No replacement oracle/root or application-specific consumption shortcut appears in the claim.

The four static encoders use the specified right-zero-padded ASCII domain and big-endian canonical 32-byte words: Config 384 bytes, Ready 224, Claim/Exit 288 with distinct domains. Fields/order agree with PortalMessages and frozen production-helper tests. Private ancestry uses `[1,board,owner,claimContent,secret]` under `0x42420101`; it stays in owned note data, not Ready/claim/exit message content. Knowledge of the secret selects the private claimant, as specified; L1 refund identity remains the authenticated original depositor.

The note stores eight Fields in the specified order and returns eleven logical values explicitly. Receipt metadata is at most 96 bits and sequence state 192 bits, both below Fr: their packing arithmetic cannot wrap. Each custom unpacker compares repacked data with its original Field, rejecting high-bit/truncation aliases. The little-endian byte extraction produces the specified three u64 limbs. No-post withdrawal pops the selected owned note, validates schema/chain/receipt/depositor, checks eligibility, and emits only the authentic exit tuple. Generic note getters remain utility retrieval, not authority claims.
