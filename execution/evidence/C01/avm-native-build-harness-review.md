A macOS Seatbelt profile allows reads and dependency networking but restricts filesystem writes to this temporary tree and `/dev/null`. Configure legitimately downloads upstream dependencies; this is not an offline build claim.

There is no runtime execution of the produced prover. `file` must identify arm64 Mach-O, and `otool -L` captures link dependencies for later qualification.

Each configure/build/inspection process has an owned detached process group. Parent sampling uses macOS `ps` at approximately one-second intervals and records peak summed group RSS; crossing 8 GiB or inability to sample terminates the group and fails. The 15-minute work watchdog, SIGINT and SIGTERM also terminate the active group and enter cleanup. Group cleanup independently attempts TERM then KILL and requires observed absence; EPERM is not treated as success. An unconfirmed group prevents temporary-tree removal. The watchdog is sampled process supervision, not an instantaneous kernel memory allocation ceiling. Final cleanup and bounded provenance capture are reported separately through total elapsed time; neither proves real AVM proof memory capacity.

Before deletion, the helper records every discovered `_deps` Git repository's actual HEAD and dirty status using read-only Git settings, disabled optional locks/fsmonitor/hooks, per-command deadlines and a bounded diagnostic window. These resolved commits improve provenance for upstream tag-based dependencies; no whole dependency-file inventory or independent supply-chain audit is claimed. Failures in this collection fail final acceptance. Stage output keeps bounded redacted head/tail snippets (no caller secrets are inherited), exit/signal, resource observations and cleanup. Compiler/source paths and public build errors remain available for diagnosis.

Successful output is retained only in fresh `.build/C01-avm-native/<UUID>/bb-avm` with byte hash, CMakeCache and final manifest. Final `passed` additionally requires source integrity, provenance capture and cleanup. The binary is not designated a production prover merely because it builds. The next qualification must inspect its actual AVM support and run genuine proof/negative controls under unchanged resource bounds before using it for the covering epoch experiment.

## Descendant supervision repair after unaccepted build 26a51ce7

Root observed CMake and Ninja sharing one process group while a compiler created its own group. The original group-only RSS/cleanup implementation therefore omitted compiler memory and could leave a compiler alive during cancellation. That run is **not accepted**, and its sampled group RSS must not be represented as total build memory. This is a harness defect; the previous review did not catch Ninja's real process topology.

Final repaired source SHA256: `56f307a61d47cf76619ac75fdee68fcc93a7aa99c70aadbce6b4b30168c91275`. The actual build-stage runner now uses exported `OwnedBuildTree`: each snapshot reads PID, PPID, process group, RSS, start time and state; computes transitive descendant membership; and remembers observed PID/start identities and owned groups across parent exit. Observed PID reuse does not inherit the old identity. Summed RSS includes descendants that start separate groups. Reports now use **peakTreeRssKiB**, with peak member observations, rather than reinterpreting old group-only metrics.

On deadline, interruption or resource failure the supervisor freezes remembered owned processes; cleanup refreshes descendant discovery while parents cannot keep launching replacement compilers, then kills tracked groups and individual descendants. It requires observed tree absence, keeps failures as failures, and retains the temporary tree if cleanup cannot be confirmed. Scope remains sampled supervision of this known compiler topology, not a kernel cgroup or proof that an intentionally escaping daemon could never appear between snapshots. Poll/sampling failure still fails closed.
