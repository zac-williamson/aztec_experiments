# P03 preparation: baseline reproductions and test seams

Prepared by the delegated build-review lane while P02 final verification was in progress. This is prerequisite-independent inspection only: P03 was not started or completed, no application source was changed, and no vulnerability experiment was executed by this preparation lane. Reproduction classifications below distinguish earlier measured results from current inspection and work still required.

## Evidence and priorities

The frozen baseline is `execution/baseline/production-readiness.md` and its `evidence/` directory. Historical source probes live outside the repository in `../review/checks.mjs`; the local EVM probe is `../review/portal-probes/src/PortalArtifactProbe.t.sol`. Their outputs were preserved in the baseline. Do not depend on those workspace-relative auxiliary files for CI: port the relevant behavior into repository-owned tests and retain hashes/fixtures for the original bad artifacts.

The current contract source, user engine, deployment engine, and daemon have no source changes relative to their reviewed starting implementations. P02 repaired their build inputs and SDK/CRS adapters, not their economic, authorization, transaction-outcome or moderation behavior. The current published V5 compatibility upgrade belongs to P04-A05 and must be reflected in later reproduction environments.

Priority order: close M01's shell/signing boundary as soon as P02 permits; reproduce wrong-portal and note-substitution constraints before designing replacements; establish fee observability and same-anchor concurrency with real local protocol execution; migrate the cheap receipt, artifact, history, and daemon-failure probes into maintainable modules. Preserve valid normal-flow controls beside every negative case.

## M01 handoff: preserve the measured shell failure while replacing the seam

Current path is `moderation.mjs:parseVerdict` → `daemon.mjs:processPost` → `flagPost` → `runCli` → `execSync`. The reason is truncated to 200 characters twice, but shell expansions remain active inside the constructed double quotes. The historical probe extracts the two functions between `function cliBaseArgs()` and `function fetchPosts()` and replaces `execSync` with a capture stub. Its marker is inert because the captured string is never executed. This is sufficient evidence of the unsafe construction boundary; do not send a historical payload through the unfixed real subprocess path to improve the demo.

The current aggregate `../review/checks.mjs` will also assert that censor init has four parameters. P02 intentionally fixes that defect, so blindly rerunning this historical aggregate now fails for the right reason. Split the reproductions by behavior, keep the original output untouched, and carry the known-bad artifact in a dedicated fixture instead of weakening the current-artifact assertion.

Suggested maintained seam:

1. Move fixed signer configuration and subprocess invocation into an importable module/factory. Its injected runner takes executable, argument array and options; use `process.execPath` and `execFile`/`spawn` without shell interpretation. The daemon's real main entry should be guarded so importing testable orchestration cannot bootstrap models, read a wallet, or start polling.
2. Expose a narrow signer action such as `flagPost({postId,reason,policyVersion})`. The model output may supply a bounded verdict/reason only; it cannot select an executable, raw action, portal, node, wallet path, or arbitrary arguments. Signer-side validation remains necessary even if the model client validates first.
3. First regression injects a capturing runner and asserts all shell-looking characters are exact inert array elements or deliberately rejected. Cover quotes, backticks, substitutions, newlines, NUL, invalid types, oversized UTF-8 data and leading dashes. The test must assert the boundary API and fixed authority, not a source-code substring.
4. Then execute the **fixed** boundary against a harmless temporary Node argv-echo fixture using a fresh temp directory and no wallet. Assert the fixture receives exactly the original reason; it performs no other operation. This tests actual OS argument handling without invoking a shell or external service.
5. Keep local HTTP-model/CLI integration tests, but adapt their injection to the narrow interface. `test_daemon.mjs` currently uses fixed port 5095 and shared filenames; switch tests to ephemeral ports/temp paths before parallel runs. Its child exit handler maps a null/signal exit to zero with `code || 0`; fix that harness defect so timeouts cannot masquerade as successful exits.
6. Model and signer processes currently inherit the daemon environment and run under its filesystem identity. Merely moving code into another module or child process does not establish M01-A04. Define the actual separation mechanism (e.g. isolated model container with only model files and bounded request channel; signer process with fixed allowlisted interface and private wallet mount), then test that model execution cannot read signer secrets. Preserve those as fresh dummy-secret fixtures, not user wallets.

`parseVerdict` is already exported and can be tested directly. It currently maps unclear output to an OK-like result, which is not equivalent to an observable moderation error. M01 should define safe malformed/unavailable responses explicitly and test them through orchestration; M02 will persist/retry unresolved work. Current real-model behavior, prompt-injection success rates, and classification quality are unmeasured, so model output security should be enforced by the interface rather than prompt assumptions.

## Other maintainable seams

The user and deployment engines export only their top-level functions through `globalThis`; their wallet/deploy helpers are nested. Prefer extracting cohesive wallet receipt handling and deployment orchestration into importable modules with dependency injection, then invoke those same modules from the app/CLI. If a temporary VM is needed to load the entire existing browser-style module, execute the complete module and its public entry with injected environment dependencies; avoid retaining brittle source slices as the permanent test architecture.

No test should equate mocked bridge success with authenticated collateral, mocked note inclusion with Noir proof soundness, worker startup with proof generation, or passing model stubs with production moderation quality. The real local test and proof gates remain required downstream. This document does not change task state or claim that any open finding has been fixed.
