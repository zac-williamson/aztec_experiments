# C02 production draft review

Read-only source review, 2026-09-14. Production draft SHA-256 `7f2c38c93b1017109c2116682005464b216c0a22ca103cb130a2d21c0e4b6e75`. No application edits, compilation, tests or proofs. The test draft was extended only in its evidence patch with root's requested dummy control; final test-patch hash is `1f65722feb5bb8e4bc99ee5b915b31ebfefdad161be592d9efa17a04273897a3` (13 proposed tests). This is an AI integration review, not an external audit or evidence that the draft compiles.

**No concrete new authorization or overflow defect identified in this draft.** It closes the inspected C02 metadata and immediate-chain checks without replacing actual membership. Remaining implementation qualification and scope limitations follow.

## Noir/API feasibility

`ScreeningScope` is an ordinary struct with inherent methods, not a new external entrypoint. The same compiled `#[aztec]` module already contains `impl Config::{hash,validate}` and `impl DepositNote::logical_fields` with unannotated methods. Pinned `macros/aztec.nr:340–352` checks module free functions for entrypoint annotations; this existing pattern supports the proposed inherent-method structure. Do not move `authenticate` to an unannotated module free function merely for style: that would run into the macro restriction. No serialization/note trait is needed for a local scope object that never enters storage or a function ABI.

`Option.is_none()` is already used in the current successfully compiled contract's hint utilities, so its availability is not speculative. `ConfirmedNote` is re-exported by pinned `aztec/src/note/mod.nr:21`; `BlockHeader` is the type already consumed by `history/note.nr`, and its `timestamp()` returns u64. `self.storage.posts.at(sender).storage_slot` matches the existing utility and actual Owned/PrivateSet implementation. Owner is separate from that slot; the draft correctly checks both.

`assert_identity` is a constraint-only helper; `authenticate` is a constrained membership helper that invokes the existing witness oracle indirectly through `assert_note_existed_by`. It should not be described as an oracle-free pure proof. Its pre/post metadata checks, standard inner hash, contract silo, settled nonce and actual Merkle membership are preserved. The expected scope is constructed from the executing address, actual caller, actual state variable and selected deposit chain; an attacker cannot pass an alternative scope into `post`.

## Transition checks and arithmetic

The deposit inequalities and zero-link/sequence equivalences establish a coherent start. Child is exactly screened+1 and no greater than head; matching head sequence is equivalent to matching the authenticated head link. Grandchild is exactly child+1 with its previous link and the same head equivalence. Missing required hints fail, and extra hints beyond the head or when nothing remains are rejected. A provided second hint is authenticated even when a non-head child is immature, preventing the former ignored-input path.

The `screened_sequence + 1` expression is reached only when screened < head, bounding screened below u64 maximum. Grandchild addition is reachable with a supplied grandchild only after a head child has already required its absence; a valid non-head child is below head and therefore below u64 maximum. Malformed over-bound values reject earlier; checked integer arithmetic must remain checked. Existing `head_sequence + 1` rejects a fully exhausted sequence counter instead of wrapping. The current early withdrawal path does not increment that counter. No new unchecked cast is introduced by these guards.

Future timestamps reject for each authenticated hint. Grandchild timestamp cannot precede its child; equality is valid. No timestamp for the previously screened note is fabricated from DepositNote fields. Authentic issuance plus committed predecessor continuity carries that preceding history. At most two candidates advance, and the grandchild requires the child to advance first. Repeated flag penalties remain tied to the one consumed live deposit and new progress. Existing timer multiplication/narrowing elsewhere is still C05 work, not newly proven safe by these additions.

## Dummies, tests and remaining boundary

Immediate maturity for an **included authentic dummy** agrees with §7: it has no censor opportunity/public flag requirement. The draft still applies the current post's cooldown and does not let a later dummy skip an immature real child. It skips public flag reads for both dummy positions. The inherited pre-C03 `_post_public` still assigns dummies public counter slots; this patch does not remove that separate behavior or claim dummy traffic is invisible.

The original 12-test draft matched guard ordering but did not distinguish immediate dummy maturity or ignoring its old public flag. Root requested and this review added a thirteenth proposed test: with a2x deposit, create/confirm a dummy at+1801, flag its actual current public slot through the authorized censor, then post at+3600. Require screenedSequence1, exact head-link carry-forward and nextAllowedTime+5400, despite the dummy being younger than3600 seconds and its old flag being set. This uses current public methods, not a storage override. C03 must migrate this intermediate fixture when it removes dummy public slots.

The metadata substitution tests first establish actual TXE membership of independently inserted notes, then call the actual board with exact expected C02 errors. Artificial test-context issuance/discovery does not demonstrate a production mint path, encrypted transport or genuine network proof. The young-second-hint control correctly uses two real posts with a shorter cooldown than censor window, so its child is non-head; otherwise “unexpected grandchild” would mask the intended wrong-owner guard. The current maintained suite has no old link-error strings requiring updates; its 17-note missing-child negative remains unchanged. All of this remains unexecuted, and the larger second-receipt/old-cycle/chronology/proof matrix is still outstanding.

The draft explicitly retains the **incomplete real-post maturity rule** based on private anchorTimestamp. It does not yet establish actual public `postExists`, publishedAt and flagDeadline, and it still casts postId to u32. C03 must introduce the independent Field identity/public records and connect screening to the matching record; C05 must enforce the late-flag/window and timing boundaries. C04 retains full-lifetime hint lookup. Do not mark the entirety of §7, public censor-window assurance, or production readiness complete merely because this bounded C02 metadata draft later passes its tests.
