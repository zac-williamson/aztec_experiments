Thirteen proposed tests: three normal controls and ten rejection controls. The normal cases prove inclusion of the actual hinted notes and exercise `Billboard.post`: a mature matching child advances exactly one sequence/link, and a matching young child/grandchild pair advances neither. Negative cases cover actual included notes with wrong contract, owner, slot, schema, chain and sequence; identical content reinserted with fresh randomness (a different authenticated head); duplicate grandchild beyond the head; a supplied included hint when no history exists; and wrong-owner second hint hidden behind an otherwise valid young child.

The fixture does **not** mutate an existing hint's metadata and then rely on membership failure. It calls actual `lifecycle::create_note` in `TestEnvironment.private_context_opts(at_contract_address)`, discovers the resulting note using `discover_note_at`, and queries actual settled HintedNote metadata through the note oracle at that contract. It selects the fresh randomness exactly once, avoiding accidental selection of the original note when content matches. Before the board rejection, a separate context calls actual `assert_note_existed_by` against the current note-tree anchor and checks the returned metadata. Expected application reasons are different from membership/setup errors, so a failed fixture will not satisfy the negative test.

Wrong-contract uses a separately deployed initializerless Billboard address for the test-only note context. Wrong-owner uses another generated account; wrong-slot uses an unused slot offset. This is **artificial note issuance through maintained TXE test APIs**, not proof that production can mint arbitrary notes under the board or that encrypted transport was exercised. `discover_note_at` intentionally emulates discovery with typed hashing and skips encryption/decryption (pinned `test_environment.nr:1481–1530`). That limitation is appropriate for isolating screening's inclusion-versus-authority boundary and must remain explicit.

The unused-second-hint case needs a real non-head child; otherwise root's new “unexpected grandchild” guard would fire first. Its two real posts therefore use a 2x deposit (1800-second cooldown), at initial time+1801 and +3600. At the third eligibility time+5400, child1 is still one second younger than the configured3600-second censor window and head2 is authentic. The same setup with the original second hint is the positive control. The negative substitutes an independently included copy owned by another account, which must fail `C02 wrong owner` even though neither candidate can advance.
