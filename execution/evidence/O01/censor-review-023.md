## Reviewed conclusions

- Parent `verifyCensorPackage` resolves an owned `.build` package, checks the pinned manifest hash, streams every manifest entry through SHA-256, rejects duplicate/escaping/nonregular/symlink entries, and matches the launcher, CLI, engine, toolchain and SDK/CRS manifests against current source. Flow copies this package into its disposable private directory; the original package is not used as writable runtime storage. The copy itself is not independently rehashed; provenance relies on the preflight-verified source remaining stable during `fs.cp`.
- Root normalizes the incumbent application's signing derivation before genesis and updates the funding address list. Board construction consumes that normalized account as censor/deployer. The flow independently restores it and asserts its actual current-censor address. Successor identity is distinct and starts with zero public fee balance.
- CLI arguments use the actual supported `author` route, `--censor-wallet`, `--node-url`, `--eth-rpc`, `--portal-address`, private-fee files and PXE prefix. Claim JSON's exact `amount`, `salt`, `leafIndex` keys match `readPrivateFeeJson`; optional secret derivation is performed by the production helper. Gas JSON names, integer strings and 16x maximum-price scaling match the production parser; fee credit must exceed the configured maximum.
- The real portal is runtime/immutable verified and remains disabled with zero collateral. Governance operations do not require collateral Ready activation. No claim of Ready proof, active-board bridge deployment or deposit lifecycle should follow from this test.
- Each owner receives a genuine L1 private-fee bridge deposit. Existing funding helper checks actual canonical receipt/event and exact Inbox membership while temporarily enabling ordinary empty checkpoints, restoring sequencer settings afterward. Commands use ordinary local L1 mining and synchronized test clock; no network epoch prover is started. Native wallet and Barretenberg singleton are closed before the packaged command executes.
- Success is not inferred from log markers. Exactly one new accepted captured transaction per command must have a nonempty proof, expected shared payer, successful included receipt, matching canonical block/effect and original hash. A fresh read-only wallet then checks private remaining credit equals bridged amount minus exactly one maximum fee; shared public payer balance equals its prior balance plus the bridge amount minus actual receipt fee. Both users' public fee balances remain unchanged.
- Transfer must set the successor while preserving current policy version. Successor policy update must yield the exact intended UTF-8 length/content, zero trailing packed bytes, and the domain-separated policy commitment computed by the shared protocol encoder. These checks match the contract's scoped policy/version behavior.
- Root branch explicitly excludes Ready/bridge flow for this mode and retains the 540-second / 2-GiB parent supervision and source fingerprints. Cleanup needs to attempt mining stop, wallet close, RPC restoration/socket close and owned directory removal independently; the in-progress owner changes address this requirement.
