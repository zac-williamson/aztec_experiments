# Censor command helper implementation

Implemented only `scripts/o01-censor-command-flow.mjs`; coordinator/package descriptor and RPC/command IO are owned separately. Pinned Node syntax check passes. No genuine command run or proof qualification performed by this agent.

The helper deploys a disabled genuine portal with verified artifact creation hash/runtime immutables, prepares actual FeeJuice bridge claims separately for the incumbent and successor, then executes the packaged transfer and successor policy commands. A complete disposable package copy preserves original package bytes while containing CLI-written PXE caches. Wallet/claim files are0600 and removed with the owned directory. Native funding wallets and native BB singleton stop before each packaged WASM command; verification reopens a wallet with proving disabled. Parent retains the existing aggregate540second/2GiB limit.

Independent checks require exactly one captured submission per command, a nonempty proof, canonical successful receipt/effect identity, shared FPC payer, exact per-owner maximum-fee debit and pooled protocol fee debit, unchanged public account balances, successor authority, exact policy bytes/padding and board-bound policy commitment. Policy version is a content commitment, **not an incrementing counter**; this corrects that wording in plan015. The portal remains disabled with zero collateral balance/liability; no Ready or collateral deposit is generated.

Incumbent account must use the application's derived signing key before genesis/board construction. The helper asserts this; root normalizes preparation before genesis. Incumbent starts genesis-public-funded for deployment, so evidence records that baseline and verifies no governance debit from it. Successor public balance starts/remains zero. `prepareW01PrivateFees` is intentionally not reused because it generates and binds a different owner; the explicit-owner bridge helper is reused instead.

Limitations: actual CLI loads the browser/WASM bundle, with no supported native-prover flag. Its CRS initializer reads the original compressed manifest; retained package lacks the browser-derived uncompressed CRS files, so repeated decompression is an observed source performance risk. This implementation does not override the CLI backend or disguise that cost. Command execution/performance remains unqualified until a bounded genuine run. Negative former-censor rejection is not included in this minimum two-command profile; generic CLI failure must not be called authorization evidence. Independent source review and real proof results remain required.
