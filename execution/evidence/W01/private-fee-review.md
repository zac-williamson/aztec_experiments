# Integrated private fee review

Review performed by root with separate private_fee_contract, private_fee_client and private_fee_ui lanes. This is internal engineering review, not an independent audit.

- Contract lane implemented ownerless balances and claim/nullifier constraints, then independently reviewed the client and actual pinned SDK APIs. It found automatic author-key substitution during FPC registration in the application wallet. The UI lane removed that override and added an actual BaseWallet regression that also reproduces the old failure.
- Client lane implemented payment and funding/recovery helpers, then reviewed proof routing and Noir bridge-secret/nullifier reconstruction. It found the initial fixture reused the deployment sender and bypassed production recovery. The fixture now uses a separate disposable sender, real production funding/recovery helpers and persisted public recovery metadata.
- A real integration attempt exposed stale Ethers pending-nonce caching after token approval. A disposable Anvil reproduction confirmed cached nonce zero while the node reported one. Deposit nonce selection now respects the confirmed approval nonce, with a regression and finite safe failure diagnostics.
- Initial TXE positive fee-election calls failed because pinned TXE starts top-level calls after setup. No contract or TXE weakening was made. Eight applicable constraints stay in TXE; genuine cold-start, standalone payment and subsequent application transactions verify positive fee election and exact private/public accounting.
- Public compiler-generated dispatch is distinguished from source public functions. Canonical artifact checks reject initializer/admin/public entrypoints while allowing the generated dispatcher. The contract itself has no administrator or operator service.
- Coupon-specific board entrypoints, contract packages, service, storage and obsolete test fixtures were removed. Historical evidence remains explicitly historical. SDK and generated consumers use only the replacement payment classes.

Residual boundaries: maximum-fee charging has no unused-gas refund; L1 funding and cold-start amount/timing are observable; RPC/host metadata is not hidden. Native genuine journeys and real built-browser SDK smoke are distinct checks, not a claim that a browser-generated proof was exercised. Production release and independent review remain later gates.
