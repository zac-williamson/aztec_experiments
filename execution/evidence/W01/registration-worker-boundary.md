# Operator registration worker boundary

The worker performs one bounded preparation/submission or reconciliation step. It requires a trusted local signer callback and an explicit recovery-fence callback; it cannot start without them. The HTTP issuer has no access to either callback and exposes no signing or administration endpoint.

A new step seals the local issuer batch, binds its scope and immutable tuple in the journal, checks the actual sponsor deployment/network/board and current admin, prepares the fixed register_batch call, and persists its exact serialized transaction before marking submission uncertain and sending. The journal independently decodes the transaction and recomputes its public calldata hash and transaction hash. The worker asks the node to validate the proof and simulate public calls before spending a fee. It never logs transaction bytes or signer errors.

After interruption, recorded transactions are reconciled by exact hash. No missing response creates a new proof or automatic resend. A claimed preparation without persisted bytes is an explicit recovery stop. A canonical successful receipt must also match the actual registered batch. Canonical-block or registered-state mismatch marks the journal blocked, fencing further preparation/submission. A checked inclusion releases the single submission slot; included records remain available for finality/reorg monitoring. No network epoch proof or finality wait is part of ordinary batch registration.

The worker's callbacks and RPC responses are trust inputs, not cryptographic attestations manufactured by this module. The local genuine test supplies a fence justified only by its freshly created disposable genesis/contracts/private directory. Production still needs the actual operator process lock, external recovery/backup history, issuer admission fence, bounded scheduler, retention, funding/outage handling and alert policy. A whole-database rollback cannot be detected by comparing that database to itself. Runtime code must not replace the fence with an unconditional true callback outside this explicitly local test.

The24 component controls use real SQLite, contract instance/ABI/transaction codecs and actual competing/crashed processes, with explicit node/issuer/proof doubles in the worker cases. They do not establish proof validity. Genuine node proof validation and restart reconciliation are qualified separately by the narrow --sponsor-registration supervisor. Public service deployment remains unauthorized and unperformed.
