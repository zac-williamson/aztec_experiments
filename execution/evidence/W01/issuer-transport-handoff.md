# Restricted issuer HTTP and browser transport

Scope: transport boundary only. No deployment, public listener, batch administration, funding, signing, canonical registration, provider integration or claim that W01 is complete.

`createIssuerHttpServer({issuer, allowedOrigins, maxBodyBytes, maxConcurrent, maxRequestsPerMinute, requestTimeoutMs, headerTimeoutMs})` in `sponsor-service/http.mjs` returns `{server, counters}` without listening. Pass the awaited `openIssuer` result. The caller owns listener binding and shutdown. Only exact POST `/reserve`, `/submit`, `/retrieve` routes exist; requests use the core's exact field sets. A local operator must separately seal a batch. Neither sealing nor any administrative operation is exposed over HTTP.

Defaults are 4096 request bytes, 16 active operations, 120 requests per fixed minute window, 5-second request/header deadlines and 8192 header/response bytes. Admission counters and limits are process-global, not keyed by IP, owner or token. Unknown paths/methods, credentials/cookies, compressed bodies, malformed JSON, extra core fields and oversized bodies are rejected. CORS allows only configured exact origins and POST/content-type preflight; there are no wildcard or credential allowances. Every application response carries no-store/nosniff/no-referrer. Internal exception text is never returned, and the implementation does not log requests, bodies, tokens, IPs or headers. Rejected requests close their connection. Invalid HTTP parser/upgrade/CONNECT traffic is disconnected without logging bytes.

`createSponsorTransport({url, allowLoopbackHttp=false, timeoutMs=5000, maxResponseBytes=8192, fetchImpl=fetch})` in `shared/sponsor-transport.mjs` returns `{reserve, submit, retrieve}`. The explicit URL must be an HTTPS origin without credentials, path prefix, query or fragment. HTTP is accepted only with the explicit loopback test option and a loopback host. Fixed POST calls omit credentials, suppress referrers, disallow redirects and disable caching. Input fields are checked before network access. Responses are streamed under a byte cap, validated against exact shapes and canonical field/integer bounds, and the reservation window must match the request. An absolute deadline races both connection and stream reads; cleanup requests cancellation without waiting indefinitely for a custom fetch implementation. All client error messages are fixed codes. It never automatically retries an ambiguous request.

The HTTP client validates structure, not cryptographic membership or chain registration. Existing sponsor-client/canonical provider integration must independently verify those before use. Retrieval always requires `registration: "pending"` and `usable: false`; a remote server cannot promote a response to usable through this transport. Owner, blind, keys, action and authorization witnesses are not request fields.

Validation: Node 24.21.0, **18/18 passed**, actual ephemeral 127.0.0.1 HTTP listeners and SQLite state, including reservation/submission/sealing through the local core/retrieval, exact CORS, strict payloads, caps on declared and chunked bodies, partial-body deadline, oversized headers, active/rate limits, safe error mapping, browser request options, malformed membership shapes, oversized responses and stalled fetch/stream deadlines. Five-second test watchdogs apply. Tests use no public endpoint or chain; fake fetch/issuer operations are explicit and limited to protocol/error/deadline tests. All successful-run servers, connections, temporary databases and the hash singleton are closed. The earlier sandbox-denied attempt is retained as `issuer-transport-tests-sandbox-denied.log`; it is not an application failure or passing HTTP evidence.

Remaining operational work: trusted TLS/reverse-proxy configuration, endpoint/provider wiring, access-log disabling and retention policy across infrastructure, public abuse/admission policy, persistent/distributed rate control, connection-level protection and service supervision. The fixed-window rate limit resets on process restart and does not prove resistance to distributed abuse. Node deadlines run on its event loop (header checks use Node's periodic checker); they do not preempt synchronous SQLite/CPU work. Timed-out underlying issuer operations retain their active slot until settled, so they cannot bypass the concurrency limit. Proxy deadlines and process supervision remain necessary. A timed-out reservation can consume capacity without delivering its token; no retry/idempotency or reliable token-delivery protocol is invented here. OS/network/proxy operators can observe connections even though this implementation collects no identity records. Whole-database rollback and canonical registration remain the core's explicit external reconciliation limits.
