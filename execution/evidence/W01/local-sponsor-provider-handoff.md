# Local wallet-derived sponsor provider

Await `createLocalSponsorCouponProvider({walletSecret,sponsorAddress,windowDuration,issuerUrl,createStore,allowLoopbackHttp=false,maxPolls=30,pollIntervalMs=1000,deadlineMs=30000,transportTimeoutMs=5000,nowSeconds})` from `shared/local-sponsor-provider.mjs`. Required wallet secret and sponsor address are canonical nonzero32-byte lowercase Fr hex strings. Duration is a canonical decimal string in1..86400. Existing provider bounds are retained: polls1..30, polling0..5000ms, acquisition deadline50..60000ms; transport deadline50..30000ms. Optional nowSeconds is a trusted local clock callback. Unknown options are rejected. HTTPS origin validation, explicit loopback-only test HTTP and fixed anonymous requests come from the actual shared transport.

The factory derives AES-GCM256 via WebCrypto HKDF-SHA256 from the existing wallet secret. HKDF salt is UTF-8 `AZTEC_BB_LOCAL_COUPON_STORE_HKDF_SALT_V1`; info is UTF-8 JSON of `["AZTEC_BB_LOCAL_COUPON_STORE_AES_GCM_V1",canonicalSponsorAddress]`. The derived CryptoKey is non-extractable with encrypt/decrypt usages. The temporary byte-array copy of the wallet secret is cleared after key import. JavaScript strings and WebCrypto internals are not claimed securely erased. This uses an existing cryptographic wallet secret, not an added password or password-hardening mechanism.

The trusted local `createStore({encryptionKey})` callback selects the actual SQLite CLI or IndexedDB browser adapter and supplies its local path/name. It receives no wallet secret, owner, blind, issuer URL or transport object. There is no fallback adapter. A returned adapter must support pending/put/markAttempted/close. The actual shared transport and coupon provider are then composed; only the latter handles local owner/blind state. The return exposes only acquire and async close. Close is idempotent and blocks all later acquire calls. Acquisition retains existing provider safe errors; all initialization and close failures become `SPONSOR_LOCAL_PROVIDER_UNAVAILABLE`. Partially initialized adapters are closed on failure, and unsafe exception text/getters are not exposed.

HKDF binds wallet and sponsor, **not** chain, board or issuer origin. Chain/board/rollup/portal/owner scope remains in the provider's authenticated encrypted record and opaque local partition. Reusing the same database file with a different wallet or sponsor fails decryption rather than opening another partition; callers should select the appropriate local store namespace. Existing wallet unlock/security and trusted local adapter code remain prerequisites. The wrapper supplies no on-chain registration, transport privacy network, operator service, production key backup or database rollback protection. Closing during an active acquisition is not a cancellation API; the caller should finish or supervise active work before closing.
