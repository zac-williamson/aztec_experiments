## Reviewed implementation invariants

Use deployment-fixed nonoverlapping windows: positive duration, window index derived from timestamps, inclusive expiration one second before the next window starts. Check timestamp arithmetic before conversion. Each window has an immutable spending ceiling; batch registration runs publicly and atomically reserves `ticket_count * max_fee_per_ticket` against current public reserved balance. Require positive bounded count, and check `max_fee_per_ticket <= remaining / ticket_count` before multiplying. Never reclaim reservations or confuse these worst-case commitments with actual spending.

Batch IDs and roots are immutable and cannot be reused. Coupon membership binds chain, protocol version, sponsor, window, batch, index, owner and secret blind; enforce `index < ticket_count <= tree capacity`. Single-use storage includes batch and index and the committed owner. Reads from old private anchors are safe only for immutable policy/batches. Administration rotation controls future registrations, not immediate revocation of outstanding tickets. Every sponsored root lowers actual transaction expiration to the immutable window end. Gas fee caps remain bounded to u64 unit prices with u32 gas quantities and checked u128 totals.

These invariants were reviewed against the pinned PublicImmutable, fee fixture and expiration APIs by the bounded review lane. Implementation and acceptance tests remain pending; this is design review, not proof of behavior.
