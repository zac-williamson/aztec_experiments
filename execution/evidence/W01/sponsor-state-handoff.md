# Read-only registered sponsor batch helper

`shared/sponsor-state.mjs` exports `readRegisteredSponsorBatch({wallet,node,sponsorAddress,sponsorArtifact,boardAddress,expectedChainId,expectedVersion,batchId})` and fixed-code `SponsorStateError`. All eight fields are required; extra fields, including owner/key material, are rejected. The caller supplies the trusted bundled sponsor artifact and deployment scope. No signatures, authwits, funding, proof or send operations are called.

Checks precede contract registration: canonical nonzero addresses, nonzero u64 batch ID, bounded chain/version inputs, agreement of both wallet and node with the expected chain/version, exact `BillboardSponsor` artifact name and three private roots, static public read ABI, current and original installed class IDs, and recomputed instance address. Only the verified sponsor instance is registered with the wallet. Two actual SDK interactions simulate `get_config` and `get_batch` using `NO_FROM` and `skipFeeEnforcement:true`. The immutable board must equal the expected board; basic window/fee policy and batch bounds are checked. Zero-root/zero-count unregistered batches and counts over1024 fail with `SPONSOR_BATCH_UNAVAILABLE`. Provider exception messages and diagnostic metadata are not propagated.

Success returns a frozen, serializable object containing exactly `{root,window,ticket_count,timestamp}`: root is canonical 32-byte lowercase Fr hex, all remaining values are canonical decimal strings. Timestamp comes from `node.getBlock('latest').header.globalVariables.timestamp`, not from the simulation result or a local wall clock. The helper intentionally allows a correctly registered historical batch; the provider/coupon preparation layer remains responsible for active-window, membership, gas, balance and authorization checks. These are provider-backed reads, not a consensus proof or an assertion of a common pinned snapshot across independently progressing node/PXE views. Config and batch registration are immutable, but the timestamp can be newer than the simulated view. Callers must handle temporarily unavailable state and apply their outer RPC/service deadline.

Validation: **28/28 passed**, pinned Node24.21.0, actual SDK artifact parsing, class computation, instance-address computation and ABI encoding/decoding with explicit lightweight wallet/node doubles. Cases cover wrong individual or mutually agreeing chain/version, absent/mismatched/forged instance, wrong artifact/private-root inventory, immutable target mismatch, invalid/unregistered/oversized batch, unsafe u64 values, extra owner field, malformed address/timestamp, overflowing window, invalid policy and safe errors. All tests assert no authorization. The success test distinguishes the actual node timestamp123 from the simulated timestamp999. No network, proof, deployment or new build was run. The initial field-codec mismatch and corrected passing run are both retained.
