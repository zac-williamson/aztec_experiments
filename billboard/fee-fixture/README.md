# Restricted sponsor feasibility fixture

This independent Aztec 5.2 / Noir beta25 workspace is an experiment for W01. It is not the production board or a deployed fee service.

`RestrictedSponsor` may be entered only as the private transaction root. It checks one of two fixed coupon leaves, elects itself fee payer, consumes an owner-bound `SingleUseClaim` in setup, ends setup, then invokes exactly `FeeTarget.delegated(owner,value,nonce)`. The target requires the configured sponsor and the real owner's private authwit. The target only queues its own public counter update; it accepts no arbitrary call list.

Deploy the sponsor with a disposable policy administrator, deploy the target referencing that sponsor, then initialize the sponsor's `PublicImmutable<Policy>` once. This avoids a contract-address/coupon-root cycle. The policy cannot be rotated, extended or replenished in this fixture. A coupon leaf is `poseidon2_hash_with_separator([chainId,rollupVersion,sponsor,epoch,index,owner,blind],0x57463031)`, with index 0 or 1; the tree uses Aztec's default binary Merkle hash. The supplied sibling and private owner/blind must reconstruct the fixed root.

The policy limits actual transaction gas, reserved teardown gas, maximum unit fees, priority fees, total fee per ticket and the aggregate worst-case cost of both tickets. Maximum unit fees are restricted to u64 so the gas×price arithmetic cannot overflow u128. Teardown is a reservation within total gas. The sponsor checks anchor validity and constrains the protocol expiration timestamp. A price of zero is allowed for TXE testing; funded local-chain tests must use real network fee estimates within these bounds.

Coupons bind private owners, but they do not publish owners. Claim nullifiers use the owner's private app NHK and a per-index storage slot. This is a primitive-level observation, not proof that issuer, RPC, timing, or funding observations cannot correlate users. An issuance service, private leaf exchange, budgeting across successive batches, production funding, outage behavior and real proof qualification remain separate work.

Artifacts are generated in ignored `target/`: `fee_sponsor-RestrictedSponsor.json` and `fee_target-FeeTarget.json`. The `application/` directory is the target's source package. The workspace intentionally does not alter `../Nargo.toml` or any production board ABI. Pure tests exercise the same policy helpers called by the sponsor. TXE tests use the actual exported private-call oracle with no sender and real Schnorr-account authwits; TXE uses zero fee prices and is not mainnet or real-proof evidence.

Run with the repository's pinned Node: `node billboard/fee-fixture/run.mjs compile`, then `process`, `pure`, and `txe`. The runner stages only fixture Nargo/Noir files under `.build/W01-fee-fixture` because Nargo selects the parent Billboard workspace from the nested source directory. It binds generated artifacts to source hashes and checks all embedded dependency sources against the full pinned dependency inventory. It does not alter the production artifact guard, whose expected source set is specific to Billboard.

The pinned TXE forces all private calls into the revertible phase (`minRevertibleSideEffectCounter=1`), even with a no-sender root. Therefore its suite includes an explicitly named observation of that limitation, not a passing sponsored transaction. It independently tests pre-election checks and a real delegated call with owner authwit. Full sponsor→target composition, inclusion expiry, coupon replay/consumption on public revert and funded fee behavior require the separate local PXE/network harness. The earlier attempted composed tests and actual failure are retained in W01 evidence.
