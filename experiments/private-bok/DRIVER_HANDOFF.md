# Actual-chain fixture handoff (not execution evidence)

The lead owns the existing supervised fixture, account setup, service lifetime, proof mode, mining, time advancement, global build inventory and eventual integration. `measure.mjs` now exports the executable `runPrivateBokExperiment` consumer, following `experiments/avatar/measure.mjs` and the existing `proveApplicationAction` helper. No service is started here. The consumer has not yet run against a chain; do not mistake syntax/pure tests or the TXE suite for a driver result.

## Consumer boundary

Pass `{node,wallet,mineL1,outputDirectory,realProofs,mark,owner,operator,otherUser,deployPortal,activatePortal,funding,redeem,advanceTo,payerMode,privateFeeAction,harnessFiles}`. Each actor is a fresh disposable registered Aztec account controlled by the fixture. The protocol probe board is an actual deployed `InvocationProbeBoard`, not an actor account. Explicit `payerMode:'private'` uses the existing `privateFeeAction`; `payerMode:'genesis'` is publicly identifying and privacy-unqualified. `harnessFiles` is a nonempty list of repository-relative fixture/helper source paths, bound before/after the run. The integrated checkout must contain the lead-owned `shared/rolling/invocation.mjs`. Do not attach developer credentials to the consumer.

The implemented consumer requires `funding.mode:'real-portal-deposit'`; no message injection callback is accepted. `funding.submit({operationId,portal,escrow,chainId,rollupVersion,amount,recipientCommitment,secretHash,content})` must lock actual disposable tokens in the real local `PluginPortal`, verify canonical L1 receipt/token deltas and journal the sole send. Return `{mode,canonical:true,portal,escrow,chainId,rollupVersion,amount,recipientCommitment,secretHash,content,leafIndex,messageHash,txHash,blockHash,blockNumber,evidenceRef}`; numerical quantities are bigint, addresses/fields may be their canonical strings. The consumer compares returned envelope fields, recomputes the installed `L1ToL2Message` hash, verifies its actual node membership path against the canonical anchor root, and then submits the real private `claim`. Bridge secret and recipient salt remain in consumer memory and are never returned in shared evidence. A lost process must checkpoint and reconcile rather than repeat a deposit.

Because escrow and portal refer to one another, the consumer deploys escrow before calling `deployPortal({operationId,escrow,chainId,rollupVersion})`, which returns the deployed `EthAddress`. After its actual `set_portal` transaction, the consumer passes `{portal,escrow,txHash,expectedLeaf}` to `activatePortal`. The fixture must settle the exact READY message, activate the portal and return `{activated:true,evidenceRef}`. Controlled local settlement must retain its explicit non-production label in the fixture evidence.

Each real private/operator withdrawal passes `{label,portal,escrow,txHash,expectedLeaf,recipient,amount,nonce}` to `redeem`. The callback must settle the exact canonical message and withdraw once on L1, then return `{passed:true,evidenceRef,recipientBalanceBefore,recipientBalanceAfter,portalBalanceBefore,portalBalanceAfter}` with bigint balances. The consumer independently asserts recipient increase and portal decrease equal the exact authorized amount. It returns only a serializable report, including canonical withdrawal records; no wallet, private notes or `Contract` objects escape through the report.

`advanceTo(timestamp)` is owned by the disposable local fixture's existing date/L1 controls. It must establish an actual canonical **L2** block at or after the requested timestamp and synchronize PXE. Advancing only L1 time is insufficient. The consumer does not monkeypatch node time or silently bypass deadline checks.

5. Await successful CHECKPOINTED/PROVEN/FINALIZED receipt through the parent's miner. Reject dropped/reverted receipts.
