# Single funding router — next fresh deployment

Signup (`fund`/`fundUsdc`) and Bok-only ETH purchases (`buyCredit`) use the same
`RollingFundingRouter` address and code hash. There is no separately deployed
Bok credit router and no `config.bokTopup` field. The browser derives the purchase
scope from `config.aggregateFunding`; the purchase ABI/event and one-payment
flow are unchanged.

Posting credit uses these same `fund`/`fundUsdc` entrypoints with zero collateral
and zero Bok allocation. ETH takes one wallet transaction with no collateral
consent. USDC takes one EIP-3009 authorization through the existing signup relay;
the user needs no ETH, and the bounded USDC payment includes relay reimbursement.
Both paths recover and claim only the private fee receipt using the existing
aggregate journal and private custody. Disabled collateral fields must all be
empty/zero, and unexpected collateral or Bok deposit events reject recovery.

Build the router with the normal contract build, or the existing constrained
`node scripts/build-funding-router.mjs` when only allowed router inputs changed.
The `--bok-credit` mode is removed. The normal deployment operator still uses the
six constructor arguments and verifies the nine immutable values, current portal
bindings, bytecode, and canonical deployment receipt. Both artifact validation
and deployment require the combined router's purchase entrypoint/event.

For the next campaign, run only router-prepare/router-send/router-status after
Board, FPC and Bok portal qualification. Do not run credit-prepare/credit-send/
credit-status or create credit-router plan/result files. Generate public wallet
fields with privateFee, aggregateFunding, and bok only. Fresh config generation
must remove the retired top-level bokTopup field from its template; credentials
and security settings are retained. The full source payload must omit the retired
standalone artifact and remove it from the new inactive release, along with Git
source deletions. Do not alter an already running release or reuse its old router
address for this ABI.

The existing credit fixture is now RollingFundingRouterCredit.t.sol and the local
EVM runner is scripts/test-funding-credit.mjs. The combined router has been exercised with focused local Forge tests, including
fee-only ETH and USDC authorization, refund, replay, and rollback cases. These
checks do not qualify live liquidity or native cross-chain inclusion. Release
artifacts and deployment receipts must still be generated by the normal pipeline.
