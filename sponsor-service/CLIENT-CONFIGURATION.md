# Configure local coupon delivery

The sponsor endpoint and contract must be operated and verified before authors can post. These client adapters do not deploy, fund or administer the sponsor. Production operator registration, recovery and release qualification are still in progress.

Browser configuration is a public `window.billboardSponsorship` object with exactly four fields: `issuerUrl`, `sponsorAddress`, `windowDuration` and `gasSettings`. Supply it before an author action. The issuer URL must be an HTTPS origin without a path, query, fragment or credentials. Use the canonical sponsor address and fixed window duration from the verified sponsor contract. The gas settings contain `gasLimits`, `teardownGasLimits`, `maxFeesPerGas` and `maxPriorityFeesPerGas`, with the exact Aztec gas fields and bounds checked by the client against the deployed sponsor policy. Do not copy local test gas caps into a deployment.

The standard CLI accepts the same public object in a local JSON file through `--sponsor-config <file>`. This cannot be combined with the existing trusted executable `--sponsor-provider` option. The CLI rejects unknown fields, invalid endpoints, malformed bounds and unsupported files. Configuration contains no wallet secret, retrieval token, blind or encryption key.

Both routes derive the coupon encryption key locally from the already unlocked Aztec wallet secret and the sponsor address, using a separate versioned HKDF domain. No additional user password is required. Browser storage uses real IndexedDB. The CLI uses a private SQLite database in `sponsor-coupons-v1` beside the selected wallet, with an opaque per-wallet/sponsor filename. Key and namespace derivation are local; neither is sent to the issuer. Wallet or sponsor changes isolate the storage namespace.

Before an author action, the local provider durably saves its reservation and blind, submits only the opaque commitment, verifies membership against the checked deployed batch, and atomically marks the coupon attempted before handing it to the transaction preparer. It resumes pending deliveries after interruptions, but does not reuse a handed-out coupon or silently fund the author. Errors, exhausted budgets, unavailable batches and invalid sponsor configurations stop the action.

The browser closes its provider after the action (including an action failure); CLI cleanup closes its standard provider before exiting. Storage survives reopening with the same wallet and sponsor. Loss of the wallet secret prevents decryption, and restoring an older whole database is not a supported way to recover spent coupons. Retention limits and issuer availability can prevent fresh issuance. These controls do not provide network anonymity, prevent request-timing correlation, or protect an unlocked browser from hostile same-origin code.

An explicitly supplied custom local provider remains trusted executable code. It receives local owner/action metadata and must honor the same no-remote-secrets boundary; the standard static configuration avoids requiring authors to supply such code.
