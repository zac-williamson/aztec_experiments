# Composer costs, gifts and conversation navigation — 2 November 2026

The composer requests an actual simulated network charge in the existing wallet
Web Worker. Native simulation constructs the exact selected-credit transaction,
including thread/Bok calls and refund allocation; its successful public effect
supplies the estimate at predicted base plus priority gas prices. It does not
prove, broadcast or create a financial workflow record. Maximum authorization
remains separate and is checked again on submission.

Typing coalesces requests. Edited, dismissed or superseded drafts cannot publish
stale results. The pending amount is a blurred rectangle; Post is never disabled
because an estimate is pending. The worker gives foreground actions priority and
drains any already-started native phase before reusing the same PXE.

FEE displays use two decimal places with BigInt arithmetic; labelled ceilings
round up. ETH/USDC precision and approved payment values are unchanged. New
posting-credit default amounts are selected at two decimals, rounding up.

The reader has a heart-dollar gift button. Its confirmation identifies the
20.00-credit gift and additional network fee. Cancel/Escape sends nothing;
another completed gift remains possible. Conversations have a Back arrow that
uses app history and existing scroll restoration. Direct links return Home.

and navigation checks, 15 release UI helper checks, 5 scheduler/MessageChannel
checks, and targeted native-fee constructor/simulation checks passed. Native
simulation checks use labelled SDK fixtures; they are not testnet acceptance.
